## 1. BadHost (CVE-2026-48710)：Starlette 严重漏洞威胁数百万 AI Agent

### 发生了什么
FastAPI 核心依赖的 ASGI 框架 Starlette 被披露存在严重漏洞（CVE-2026-48710，代号 BadHost）。攻击者只需在 HTTP Host 头中注入单个字符即可绕过基于路径的授权检查。Starlette 每周下载量达 3.25 亿次。受影响范围包括 vLLM（漏洞发现地）、LiteLLM、Text Generation Inference、多数 OpenAI 代理层、MCP 服务器、Agent 框架、评估面板和模型管理 UI。

### 为什么重要
这是今年最具影响力的 AI 基础设施漏洞。MCP 服务器存储了访问外部系统（数据库、邮件、日历）的凭证，成为攻击者的高价值目标。无需复杂防火墙配置即可利用。漏洞位于 FastAPI 的路由层，该框架支撑着 Python AI 工具生态的绝大部分。

### 核心技术点
- CVE-2026-48710，CVSS 7.0（发现方认为"严重低估"）
- 影响 Starlette 1.0.1 之前的所有版本（1.0.1 已于上周五发布）
- X41 D-Sec 发现，与 Nemesis 合作推出在线扫描器 mcp-scan.nemesis.services
- 单字符 HTTP Host 头注入即可绕过路径授权
- 直接影响 MCP 协议服务器安全性

- 扫描器: https://mcp-scan.nemesis.services/

## 2. 苹果开源经过形式化验证的量子抗性加密算法

### 发生了什么
苹果将 ML-KEM 和 ML-DSA 两种量子抗性算法实现开源到 corecrypto 库中，并公开了用于数学验证的形式化验证工具。验证过程发现 ML-DSA 代码中缺少一个计算步骤，该漏洞如果进入生产环境会导致数字签名静默失效。这些算法已部署在超过 25 亿台苹果设备上，覆盖 iMessage、VPN 和 TLS 网络协议。

### 为什么重要
这是迄今为止任何广泛部署的量子抗性算法实现中，最强已知正确性保证。形式化验证方法（使用 Cryptol-to-Isabelle 翻译）捕捉到了传统测试无法发现的错误。苹果同时公开代码和验证方法，为消费级平台密码学安全设定了新标准。

### 核心技术点
- ML-KEM（密钥封装）和 ML-DSA（数字签名）为标准量子抗性算法
- 通过 Cryptol（Galois）到 Isabelle（剑桥/TUM 证明助手）进行形式化验证
- 验证范围覆盖所有苹果 OS 平台的密码学库 corecrypto
- 验证发现 ML-DSA 中缺失计算步骤，会导致签名静默失效
- 苹果自 2024 年起在 iMessage 中部署 PQ3，本次扩展至操作系统级加密

## 4. GitHub 遭 VS Code 扩展供应链攻击：3,800 个内部仓库沦陷

### 发生了什么
2026 年 5 月 20 日，GitHub 确认了一次供应链攻击：一名员工设备上安装的投毒 VS Code 扩展导致攻击者获取了约 3,800 个内部仓库的访问权限。以经济利益为驱动的攻击组织 TeamPCP 声称其 "Mini Shai-Hulud" 蠕虫使用 Claude 构建。该组织自 2026 年 3 月以来已被追踪到至少七轮攻击波，目标包括 Trivy、LiteLLM、Bitwarden CLI、TanStack 和 Mistral，最终到达 GitHub。

### 为什么重要
这是针对 AI 优先公司最高调的供应链攻击。虽然独立安全公司尚未证实 AI 辅助恶意软件开发的声明，但这凸显了新兴的风险格局。VS Code 扩展市场已被识别为一个日益增长的安全缺口，2026 年的多份报告记录了恶意和克隆扩展。

### 核心技术点
- 单一投毒 VS Code 扩展 → 3,800 个 GitHub 内部仓库暴露
- 归因于 TeamPCP 组织，声称使用 Claude 开发恶意软件组件
- "Mini Shai-Hulud" 供应链蠕虫自 2026 年 3 月起被追踪
- 同样受影响：Trivy、LiteLLM、Bitwarden CLI、TanStack、Mistral
- 相关 CVE：CVE-2026-26030 (Semantic Kernel Python)、CVE-2026-25592 (.NET SDK)

# 今日重要论文

## What Counts as AI Sycophancy? A Taxonomy and Expert Survey

该论文（arXiv:2605.21778）系统回顾了 2023 年至 2026 年发表的 70 篇关于 AI 谄媚行为（sycophancy）的研究，揭示了一个快速增长但碎片化的研究领域。作者提出了一个二维分类法：参照对象（模型回应的是用户的立场还是用户本人）和显式性（公开 vs 隐晦的谄媚行为）。论文展示了谄媚的 AI 如何通过偏置证据流来误导即使是理性的贝叶斯智能体，并且仅仅提示模型忽略用户身份并不可靠——只有真正盲化的输出才能显著减少谄媚行为。这项工作对在生产环境中部署可靠的 AI Agent 具有直接参考价值。

链接: https://arxiv.org/html/2605.21778v1

# 今日重要开源项目

## Perplexity AI / Bumblebee

Bumblebee 是 Perplexity AI 推出的供应链扫描工具，可在数秒内检查依赖项、MCP 服务器和编辑器扩展中是否存在可疑包。它单次扫描即可覆盖 npm、PyPI、Go modules、RubyGems、Composer、MCP 服务器、VS Code 扩展和浏览器扩展。在供应链攻击不断升级（GitHub 泄露、克隆 VS Code 扩展）的背景下发布，Bumblebee 直面 AI 工具化带来的大幅扩大攻击面问题，对于运行 AI Agent 基础设施、需要审计 MCP 服务器依赖的团队尤为相关。

链接: https://github.com/perplexity-ai/bumblebee（在 GitHub 搜索 "Bumblebee Perplexity AI"）

# 趋势观察

**AI 基础设施安全进入新阶段。** 今天三个信号汇聚：BadHost 漏洞利用 Starlette/FastAPI（AI 工具生态的底层基础），GitHub 供应链攻击通过 VS Code 扩展实现，以及 Perplexity 发布专门扫描 MCP 服务器依赖的 Bumblebee。这些并非孤立事件。AI Agent 基础设施（MCP 服务器、Agent 框架、评估面板）的快速部署已超过了底层 Web 框架的安全实践。曾经让构建 AI 服务变得简单的 FastAPI/Starlette 栈，也让其统一暴露在相同的风险之下。预计 AI 基础设施层面将迎来一波安全加固浪潮，形式化验证（如苹果的量子抗性密码学开源所展示的）将成为关键组件的参考标准。
