## 1. 微软SkillOpt：Agent技能成为可训练参数

### 发生了什么
微软研究院发布SkillOpt（arXiv:2605.23904），一个文本空间优化器，将自然语言Agent技能文档视为可训练的外部权重。系统通过rollout-reflect-edit-validate循环运行冻结的LLM Agent，使用独立的优化器模型对技能文档提出结构化编辑建议。只有改善验证集表现的编辑才会被接受。

### 为什么重要
SkillOpt代表了从手工提示工程到系统化技能优化的范式转变。Agent能力现在可以通过形式化训练循环进行优化，无需昂贵微调，输出是可解释、可移植的markdown文件。该框架在全部52个评估组合（7个模型×6个基准×3个执行环境）中达到最优或并列最优，包括GPT-5.5在SearchQA上+23.5的准确度提升。

### 核心技术点
- 架构：Rollout（执行任务并记录轨迹）→ Reflect（分析成功/失败minibatch）→ Edit（增/删/替换操作）→ Gate（验证集把关）
- 将AGENTS.md和SKILL.md文件视为冻结Agent的外部状态
- MIT许可证，首周3100 GitHub星标
- 支持基准：SearchQA、ALFWorld、DocVQA、LiveMathematicianBench、SpreadsheetBench、OfficeQA
- 社区已构建封装：CodexOpt 0.2.0将SkillOpt风格优化引入OpenAI Codex

## 2. OpenAI Codex Computer Use 登陆 Windows 11

### 发生了什么
OpenAI于5月29日将Codex的Computer Use功能扩展到Windows 11，允许AI编码Agent自主导航Windows桌面、管理文件、与应用交互并在无直接人工监督下执行任务。用户可通过@computer或@Paint命令触发特定操作，并通过iOS和Android上的ChatGPT应用远程监控和启动任务。

### 为什么重要
这是Agentic AI首次与大多数开发工作发生的桌面现实发生碰撞。Codex从侧边栏中的结对编程助手转变为能操控机器的操作者——能够自主测试软件、搜寻Bug和审阅文档。移动端监控能力意味着Agent可以在工程师离开工位时持续工作。

### 核心技术点
- Computer Use模式在Codex设置中切换；通过@命令指定目标应用
- 后台任务执行，通过ChatGPT应用进行移动端监控
- 继4月macOS Computer Use和5月移动端访问之后的扩展
- 属于OpenAI构建合并ChatGPT、Codex和API的"超级应用"战略的一部分
- 安全机制：按应用权限和用户监督操作模式

### 核心技术点
- 合并GitHub Copilot、Copilot Chat、Copilot Cowork和Autopilot到一个应用

## 5. Agent 技能基础设施成为开源主导模式

### 发生了什么
GitHub Trending数据和社区活动显示Agent技能基础设施正成为开源AI的主导模式。除微软SkillOpt外，revfactory/harness（设计Agent团队的元技能）、supermemoryai/supermemory（AI Agent记忆引擎）和openhuman（Rust编写的个人AI超级智能，单日+1690星）等项目都汇聚于模块化、可组合的Agent能力。CodexOpt社区项目将SkillOpt风格优化通过CLI带给OpenAI Codex用户。

### 为什么重要
技能导向工具的大爆发让人联想到npm或Docker的早期——新计算范式的基础设施。社区不再构建单体AI系统，而是竞相创建标准化、可互操作的Agent原语：技能即便携模块、记忆即可插拔层、优化框架将自然语言视为可训练基质。这标志着Agent生态正从"手艺"走向"工程"。

### 核心技术点
- revfactory/harness：设计领域特定Agent团队的元技能
- CodexOpt 0.2.0：为OpenAI Codex用户封装SkillOpt，提供CLI集成
- openhuman：基于Rust的本地优先个人AI
- supermemory：面向AI Agent的可扩展记忆API
- 模式收敛：技能、记忆、编排成为标准化层次

# 今日重要论文

## SkillOpt: Executive Strategy for Self-Evolving Agent Skills

SkillOpt（arXiv:2605.23904，微软研究院）为Agent技能文档引入了形式化优化框架。核心洞见：技能文档是Agent的"外部权重"——既然内部权重可用梯度下降优化，外部权重也应有系统化训练方法。系统通过打分rollout运行冻结目标模型，使用优化器模型提出结构化文本编辑，并以验证集改善为接受门槛。在52个评估配置中，SkillOpt训练的技能达到最优或并列最优。框架输出可解释、可移植的markdown文件——使优化后的Agent能力成为可共享的人工制品而非专有模型权重。该论文在提示工程与形式化优化的交叉领域建立了一个新子领域。

# 今日重要开源项目

## microsoft/SkillOpt

SkillOpt（github.com/microsoft/SkillOpt）是SkillOpt框架的开源实现，MIT许可证发布。首周即获3100星标和300次fork。仓库包含：完整Python训练管线（skillopt包）、六个基准的预构建配置（SearchQA、ALFWorld、DocVQA、LiveMathematicianBench、SpreadsheetBench、OfficeQA）、交互式技能训练WebUI（skillopt_webui）和完整文档。代码结构支持扩展——新基准和目标模型可通过YAML配置添加。社区采用迅速：CodexOpt已为OpenAI Codex用户封装SkillOpt，"训练技能而非权重"的模式正向各Agent框架扩散。

# 趋势观察

**Agent技能成为AI工程的原子单元。** 微软SkillOpt、revfactory/harness、CodexOpt以及更广泛的GitHub Trending数据汇聚指向一个明确的范式转变：Agent技能正结晶为AI系统的基本构建块。技能正在替代单体提示和微调模型成为首选抽象——它们跨模型提供商可移植、通过形式化训练循环可优化、作为版本控制工件可共享。这让人联想到从手工汇编到编译语言、或从手动服务器配置到基础设施即代码的演变。技能层正在成为Agent时代的"Dockerfile"：一种声明式、可复现、可优化的AI能力规范。结合Codex向桌面控制的扩展，我们正在见证Agent工程从手艺到系统化学科的快速成熟。
