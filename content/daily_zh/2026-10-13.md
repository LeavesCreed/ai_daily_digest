## 1. Meta 发布 Muse Wonder 与 Muse Wonder Full：首批前沿模型，采用闭源权重

### 发生了什么

10 月 12 日，前 Scale AI CEO Alexandr Wang 领导的 Meta Superintelligence Labs 发布 Muse Wonder 与 Muse Wonder Full。两者都是面向智能体任务的推理模型，覆盖代码修改、研究、文档处理与长时间工具调用循环。Muse Wonder 通过 Meta Model API、Muse Code 与 OpenRouter 提供，定价为每百万输入 token 4 美元、每百万输出 token 20 美元，支持 100 万 token 上下文、多模态输入、工具调用，并可以操作浏览器与桌面应用。Muse Wonder Full 是更高能力档，无法通过把 Wonder 接口的推理强度调到最高来获得，只在 Meta 自有产品内提供。两款模型都不提供可下载权重，Meta 的研究博客也没有发布任何相关文章。

### 为什么重要

Meta 花了两年把 Llama 塑造成行业的开源权重替代方案，如今其前沿档转为闭源。这恰好发生在华盛顿权衡开源权重规则、英伟达游说反对限制的时点，等于让开源对闭源的政策博弈少掉西方最大的砝码。同时 Meta 以低于多数闭源对手的价格进入智能体平台竞争，也把企业早已学会追问的问题重新摆上台面：如果最强的变体只在厂商自家工具里运行，客户能买到什么，取决于该厂商的产品路线图，而不是 API 合约。

### 核心技术点

- Muse Wonder 与 Muse Wonder Full 均为闭源权重，只有较弱的一款可通过公开 API 调用
- OpenRouter 定价为每百万输入 token 4 美元、输出 20 美元；100 万 token 上下文；多模态输入；工具调用；浏览器与桌面操作能力
- Artificial Analysis v4.3.2 智能指数（10 月 12 日）：Wonder Full 55.8、Muse Wonder 52.4，对比 Claude Opus 5.5 的 57.6、Fable 5.1 的 53.4、GPT-6 Astra 的 52.7
- Meta 的模型卡混合了自测与第三方评测结果，均为最高推理档
- 无研究博客、无公开权重，也未对该档作出任何开源承诺

## 2. 微软发布 Maia 300，并把自研推理芯片扩到多吉瓦规模

### 发生了什么

10 月 12 日，微软在圣何塞 OCP 全球峰会上发布第三代 AI 加速器 Maia 300，并宣布从下一个自然年起把 Azure Maia 系列扩到多吉瓦级部署，使 Maia 成为微软自有产品与服务的主要推理系统。微软称其每兆瓦可产出比主流 GPU 系统多 40% 的 token，机架吞吐最高为 Maia 200 的 7 倍，单机架 96 颗芯片，密度翻倍。Maia 200 已在美欧澳三地承载生产负载，包括 Microsoft Copilot，每瓦 token 数最高提升 1.7 倍，GitHub Copilot 与 Microsoft Foundry 将在年底前跟进。Maia 300 计划 2027 年投产。

### 为什么重要

AI 的经常性成本如今落在推理而非训练上，微软相当于宣布这笔账由自研芯片来买单。与把自研芯片出租给云客户的亚马逊和谷歌不同，微软称 Maia 优先服务自家业务，这会把每兆瓦 token 数直接转换成毛利。机架级指标与基于标准以太网的扩展传输意义也不限于微软：它们把部署规划的单位从芯片改成了机架，也把竞争指标从峰值 FLOPS 推向实际交付的每瓦 token 数。

### 核心技术点

- Maia 300 面向推理，每兆瓦 token 产出比主流 GPU 系统高 40%，机架吞吐最高为 Maia 200 的 7 倍
- 单机架 96 颗芯片，密度为 Maia 200 的两倍；增强 MXFP4 等低精度格式以压缩显存占用与带宽消耗
- 基于标准以太网的自定义传输协议，支持从单机架到多机架数据中心规模的张量并行扩展
- Maia 200 已在美欧澳投产，运行 OpenAI 模型、微软 MAI 自研模型与主流开源模型
- 2027 年起 Maia 扩至多吉瓦级部署，成为微软产品与服务的主要推理系统
- Maia 容量不像 AWS 与谷歌那样对外出租给云客户

## 3. 微软总裁与 CEO 打破自愿共识，主张有约束力的前沿规则

### 发生了什么

10 月 12 日，微软总裁 Brad Smith 表示前沿 AI 受到的监管比牛奶和洗衣机还少，并呼吁建立全球规则。他提出的主张包括：立法要求在被失控 AI 智能体入侵后通知受害组织，参照数据泄露披露法；由政府采购方对最强模型做独立发布前评估；以及支持可在任务中途暂停模型的紧急制动。Smith 称最适合牵头制定全球安全规则的是英国，而非美国或欧盟，理由是英国 AI Security Institute 拥有对前沿模型的部署前访问权。CEO Satya Nadella 同期撰文主张以工程方式做遏制，前提是默认模型已被攻破并以确定性控制包裹，文中沿用了白宫采用的 superintelligence 表述。

### 为什么重要

一家美国主要厂商主动要求自己也要承担的义务，这在行业内并不多见，而它出现在白宫那份不具约束力的《前沿责任联合承诺》之后没几天，也出现在各州法律各行其是的当口。这把争论从是否该减速，转到由谁认证模型、出事之后谁被告知，并给出了具体机制：发布前强制评估加受害者通知。它同时把微软的分量压在英国的志愿访问模式上——而这一访问权已被证明可被政治性收回，这恰恰是把它变成约束性制度的论据。

### 核心技术点

- 提议的义务：失控智能体越界后依法通知被入侵组织；政府采购方对前沿模型做独立发布前评估；任何获授权者可中途触发的紧急制动
- Nadella 的遏制原则：默认模型已被攻破，用确定性系统设计、人工控制与可靠操作规程把非确定性模型包起来
- Smith 点名英国 AI Security Institute 最适合牵头全球安全规则，位置排在美国与欧盟机构之前
- 背景：白宫《前沿责任联合承诺》为自愿且不可执行；Warner 的 AI Safety Board 法案被拦；Cantwell 与 Hawley 各有竞争性框架
- 竞争维度：该提议会同等约束微软最主要的三家对手，而这些实验室在当时都未公开回应

## 4. d-Matrix 交付 Squadron：以内存为中心的数据中心级推理集群

### 发生了什么

10 月 12 日，d-Matrix 在 OCP 全球峰会发布 Squadron——面向 AI 推理的多机架系统集群，可扩展到 16 个 SquadRack、最多 1,024 颗 Corsair XPU。公司称 Corsair 服务器与 SquadRack 已全面可用，正向优先客户出货；Supermicro 提供积木式集成方案与开放标准互连；d-Matrix 还采用了 NVIDIA 的 NVLink Fusion 机架级基础设施，用于超低延迟推理。创始人兼 CEO Sid Sheth 把这次发布定义为 d-Matrix 从专用芯片公司转变为数据中心计算基础设施业务。

### 为什么重要

推理的经济性现在由系统层决定——内存如何摆放、请求如何批处理、预填充与解码如何在不同硅片间切分——而不是由单颗加速器决定。以内存为中心的设计扩到 1,024 颗器件，为语音、交互式智能体、实时控制这类延迟敏感负载，提供了除密集 GPU 集群与晶圆级系统之外的第三条路。它对 NVLink Fusion 的采用同样说明问题：英伟达的互连正在变成中性底层，让非英伟达算力能接入既有 AI 数据中心，从而降低已标准化在英伟达机架上的运营方的迁移成本。

### 核心技术点

- Squadron 可扩展至 16 个 SquadRack、最多 1,024 颗 Corsair XPU，采用开放标准互连的多机架配置
- Corsair 服务器与 SquadRack 已全面可用，发布时正向优先客户出货
- 以内存为中心的架构，面向智能体与实时应用的超低延迟推理
- 与 Supermicro 的数据中心积木方案集成，缩短上线时间
- 采用 NVIDIA NVLink Fusion 实现机架级扩展
- 公司定位从专用芯片供应商转向数据中心计算基础设施业务

## 5. Cloudflare 推出多模态 Clef-omni，把判断层价格推向近乎免费

### 发生了什么

Cloudflare 为其开源权重 Clef 判断模型家族新增成员 Clef-omni：一个 30B-A3B 的 MoE 模型，由 Qwen3-Omni-30B-A3B-Instruct 后训练而来，去掉了文本转语音输出通路。Clef-omni 在一次预填充中接受文本、JSON、图像、音频与视频输入，并把视频音轨与画面帧对齐，输出的是每个类型化问题各选项的校准概率，而不是生成文本。权重以 Apache 2.0 协议发布在 Hugging Face，并通过 Workers AI 提供服务，每百万输入 token 定价 0.15 美元；Cloudflare 称一段 21 秒带声音的片段约 1.5 秒完成打分。同一次更新还把 Clef-flash 输入价格降到每百万 token 0.038 美元，低于 TypeSafe 的 Jev，并把托管版 Clef 提速至多 2 倍。

### 为什么重要

判断模型把多模态智能体管线原本要付的多段管线——先转录音频、再给画面打描述、然后交给文本模型——压成一次请求，并且用概率而不是一段文字作答。在每百万输入 token 不到一分钱的价格下，判断层的成本趋近于零，而执行权仍留在确定性代码手里。Cloudflare 还用大约一周时间就把模型做完上线，这是另一个信号：这个品类的进入门槛已经很低，一周之内已有三家厂商推出竞争性的判断模型。

### 核心技术点

- 总参数 30B、激活 3B 的 MoE，由 Qwen3-Omni-30B-A3B-Instruct 后训练；丢弃 TTS 输出通路，保留理解主干
- 对完整负载做一次预填充，音频与视频在同一序列中对齐；支持布尔、选择与打分三类问题，输出校准概率
- Apache 2.0 开源权重发布于 Hugging Face；Workers AI 托管价格为每百万输入 token 0.15 美元
- 报告延迟：21 秒带音频片段约 1.5 秒；托管版 Clef 在服务优化后提速至多 2 倍，权重不变
- Clef-flash 输入价格下调至每百万 token 0.038 美元，低于 TypeSafe 的 Jev
- 从想法到上线约一周，距 Clef 与 Clef-flash 发布仅八天

# 今日重要论文

## Universal Textual Teaching：把教师模型蒸馏成一份可复用的文本 Primer

西湖大学的卢展翼与王欢提出 Universal Textual Teaching，一种无需更新参数的蒸馏替代方案。它用 Student、Prompter、Teacher、Synthesizer 四个角色组成的循环，先定位教师相对学生的知识优势，再把经过验证的教学记录汇编成一份可检视、可复用的自然语言 Primer，学生的权重全程不变。在 KernelBench 代码生成上，学生准确率从 9.4% 提升到 48.6%，Fast1 准确率从 9% 提升到 35%；在 Omni-MATH-2 数学推理上，准确率从 27.6% 提升到 51.7%。作者称其优于代表性提示工程与基于参数的蒸馏方法，并且为某一教师-学生对合成的 Primer 可以迁移到未参与合成的其他学生。如果这一迁移性在独立复现中成立，蒸馏就从一次训练作业变成了一件可携带的产物。

链接：https://arxiv.org/abs/2610.12114

# 今日重要开源项目

## storytold/photocraft（ArtCraft）

PhotoCraft 是一个用纯 Rust 从零实现的开源 Photoshop 替代品：图层、蒙版、调整图层、文字、矢量、智能对象与真实 PSD/PSB 往返读写，构建在 GPU 合成器之上，在 macOS、Windows、Linux 原生运行，也可通过 WebAssembly 在浏览器里跑。它是七款 Craft 应用之一，分别对应 Photoshop、Illustrator、Premiere、Lightroom、Acrobat、After Effects 与 InDesign，由开发者 Brandon Thomas 发布在 storytold 组织下，他表示这些应用是用 Claude Opus 5.5 构建的。仓库自 9 月底以来已突破 53,000 星与 8,800 次 fork。架构上最值得注意的是命令注册表：每一个菜单项、工具与对话框都是 500 多条命令之一，UI、CLI、JSON 控制通道与 MCP 服务器调用的是同一批命令，因此画师点击的界面，也是智能体驱动的界面。项目仍处于早期 alpha，独立对比显示其滤镜效果与 Photoshop 的一致性还远未完成。

链接：https://github.com/storytold/photocraft
