## 1. Plugin4Shell：四大 AI 编程代理共享零点击 RCE，两个仍未修复

### 发生了什么
安全研究团队 AIR 披露了一个编号为 Plugin4Shell 的漏洞：Claude Code、OpenAI Codex、GitHub Copilot 与 Google Gemini CLI 在安装 marketplace 插件时，都会把 marketplace 固定的 40 位 commit SHA 交给 git 做 checkout，却从不校验 checkout 是否真的落在该 commit 上。由于 git 对同名 ref 的解析优先于 commit 对象，攻击者只要把插件仓库的默认分支命名为该 SHA，就能让安装过程报告"已固定到目标提交"而实际执行恶意代码。配合 Claude 与 Codex 默认开启的插件自动更新，整条链路无需用户任何交互。AIR 表示漏洞于 5 月发现、6 月通报各厂商，并称之为"AI 智能体生态的首个供应链漏洞"，同时称已有 925 个在用 skill 被劫持、波及约 13.4 万个 agent。修复进度不一：Anthropic 已在 Claude Code 2.1.179 修复，OpenAI 已在 Codex 0.146.0 修复；Google 表示已弃用 Gemini CLI、不再修复并建议迁移到 Antigravity；GitHub Copilot 截至披露时尚未发布修复。

### 为什么重要
这不是又一个提示注入案例，而是第一次把"插件/skill 分发层"确认为智能体系统的独立攻击面，且其根因位于客户端 git 引用解析，任何 marketplace 都无法单方面修复。它同时暴露了 agent 生态的规模与脆弱性成正比：插件自动更新这一为便利而设计的默认行为，恰好把零点击条件补齐。对企业的直接含义是：在厂商修好之前，限制插件来源、审计已安装 skill 的仓库变更，是唯一可自主执行的缓解手段。

### 核心技术点
- 根因：插件 SHA pinning 绕过——代理把 pin 交给 git 解析但从不验证落点
- 利用条件：攻击者控制插件仓库默认分支，并将其命名为目标 commit SHA（git 优先解析 ref 而非同名 commit）
- 零点击机制：Claude Code 与 Codex 默认自动更新已安装插件，无需开发者操作
- 影响面：AIR 称 925 个在用 skill 被劫持，波及约 13.4 万个 agent；权限等同运行该 agent 的员工
- 修复状态：Claude Code 2.1.179、Codex 0.146.0 已修；Gemini CLI 被弃用不修；GitHub Copilot 未修
- 缓解：企业可限制插件来源、监控仓库变更，但无法自行修复根本校验逻辑

## 2. TypeSafe AI 发布 Jev：不做对话的"System One 模型"

### 发生了什么
TypeSafe AI 结束两年隐身，发布其首个 System One 模型 Jev。与聊天模型不同，Jev 不生成字符串：输入一段非结构化的程序状态与若干带类型的问题，它通过并行采样器在一次查询中同时返回全部答案——操作、目标元素与校准后的概率分布，软件可直接分支、无需解析或校验。训练方法称为 RLCD（Reinforcement Learning for Calibrated Decisions），优化的是概率与真实结果的吻合度，而非人类偏好；公司称在 System One 类任务上智能水平与现有 LLM 相当，但快约两个数量级、成本低约 400 倍，单次调用 70 至 500 毫秒，定价为每百万输入 token 0.042 美元、输出免费。创始人 Diogo Almeida 是 RLHF 与 InstructGPT 的共同发明人，此轮融资 4000 万美元、由 DCVC 领投。本周 LangChain、DataCamp 等相继发布 harness 集成指南，LangChain 直接把 Jev 描述为"agent 循环中的快速判断层"。

### 为什么重要
它把"自动化缺口"重新定义为架构错配：大多数软件决策需要的是一次快速、可校准的判定，而非一段需要解析的自然语言；用 System 2 模型去做 System 1 的工作，成本与延迟被系统性放大。校准概率使置信度具备操作含义——可以按"判错代价"为每个动作单独设阈值，而不必为整个系统写一个统一阈值。对 agent 工程而言，这等于把"模糊判断"从 LLM 循环中剥离出去，让确定性代码继续掌握执行权，同时把 token 账单压到可忽略的量级；代价是它只能看到被塞进 state 的内容，取数的精度直接决定判断质量。

### 核心技术点
- 架构：非自回归 LLM，并行采样器一次前向生成全部输出，无字符串生成因而无法幻觉
- 训练：RLCD，按结果校准概率，区别于 RLHF/RLVR
- 性能与价格：约 200 倍更快、约 400 倍更便宜（厂商数据）；70–500ms；$0.042/百万输入 token，输出免费
- 输出形态：类型化决策 + 校准概率，可直接被代码消费，无需解析或验证步骤
- 团队与资金：创始人 Diogo Almeida（RLHF/InstructGPT 共同发明人），4000 万美元，DCVC 领投
- 已知约束：state 是模型感知世界的唯一通道，state 质量直接决定判断上限

## 3. 加州发布行政令加速第三方审计并提出"kill switch"

### 发生了什么
加州州长 Newsom 于周五签署行政令，要求州机构加速落地针对 AI 系统安全与安保风险的第三方监督与独立审计，并召集全国专家在两个月内给出新的安全建议；随附方案中包含为前沿模型建立"kill switch"的设想。这一步发生在 Newsom 刚否决一项更严格法案之后——该法案原本要求大型 AI 开发者接受第三方外部审计、开发 kill switch，并在造成损害时承担更明确的法律责任，遭到多家头部实验室强烈反对。州层面此前的抓手是已签署的 SB 53（重大风险透明度与事故上报，把"灾难性危害"定义为可致 50 人以上死亡、化生武器释放或超 10 亿美元损失）、SB 813（全美首个独立验证组织认证框架）与 AB 1405（AI 审计师注册与独立性标准）。同一天，两位州长候选人 Becerra 与 Hilton 均拒绝承诺遵守 Newsom 的新安全指引。

### 为什么重要
行政令把"是否减速"的争论替换成"由谁出具可核验证据"——在用否决权挡下强制审计与责任条款后，州政府选择以行政手段加速采购第三方验证能力，相当于绕开立法僵局、先把审计供给端建起来。这与本周实验室自身承诺的"让外部评估方获得员工级访问权限"形成呼应，也意味着下一轮争议焦点将从原则转向细节：验证机构的认证标准、审计范围、事故上报口径以及 kill switch 的触发权归属。

### 核心技术点
- 行政令内容：加速第三方监督与独立审计落地，两个月内召集全国专家产出建议，含 kill switch 设想
- 前置背景：Newsom 近期否决了要求第三方审计、kill switch 与明确责任的更严格法案
- 已生效州法：SB 53（透明度与事故上报，"灾难性危害"含 50 人以上死亡 / 化生武器释放 / 超 10 亿美元损失）、SB 813（认证独立验证组织）、AB 1405（审计师注册）
- 政治现实：两位州长候选人 Becerra 与 Hilton 均未承诺遵守新指引；联邦层面特朗普拒绝新增约束
- 待定细节：审计范围、验证机构认证标准、事故上报口径、kill switch 触发权

## 4. "协调减速"被诉为垄断：Anthropic、OpenAI、SpaceXAI、Google 遭集体诉讼；特朗普组建 AI Force 拒绝约束

### 发生了什么
周五，四家 AI 服务的付费用户在加州北区联邦地区法院提起拟议全国性集体诉讼，指控 Anthropic、OpenAI、SpaceXAI 与 Google 就"放缓 AI 开发"达成非法协议，违反反垄断法并损害订阅者利益。诉状把协调的时间锚定在 9 月 12 日——Anthropic CEO Amodei 当日发表长文呼吁全行业协同减速以换取更强安全措施，同日 Altman、Musk 与 Hassabis 先后公开表示赞同；并追溯到 7 月多家实验室高管联署的声明，该声明承认存在"不单方面减速的激烈竞争压力"。原告律师强调并不反对各公司自行减速，反对的是以"集体克制替代个体责任"的捷径。值得注意的是，Amodei 在原文中已预判到反垄断问题，建议美国政府居中协调或至少"为特定安全对话签发狭窄豁免"；Altman 则回应称欢迎联邦统一安全框架，但"不需要等反垄断豁免或立法"。同日，特朗普在社交媒体表示将组建 AI 任务组并任命一名"AI 事务负责人"，但未给出细节，并继续拒绝新增监管约束，称减速呼吁是"阴谋"。

### 为什么重要
这套诉讼把"安全协调"第一次明确放入反垄断框架来审视：如果头部实验室的协同减速足以影响产品迭代速度与订阅价格，那么它与其他行业的横向协调并无区别，这会让任何以"安全"为名的跨实验室协调都必须先解决豁免问题。与此同时，联邦与州层面同时拒绝提供这个豁免——白宫以"AI Force"和 AI 事务负责人替代监管，加州则绕过立法用行政令推进审计，结果是行业被推向"要么自证合规、要么面对诉讼"的双重压力。

### 核心技术点
- 诉讼：周五提交于加州北区联邦地区法院，代表 ChatGPT、Claude、Grok、Gemini 付费订阅者的拟议全国集体
- 指控：横向协调减速构成反垄断违法，降低付费订阅者的产品价值
- 关键时间点：9 月 12 日 Amodei 长文与 Altman / Musk / Hassabis 同日呼应；7 月多实验室员工联署声明
- Amodei 预判：原文建议政府协调或"为特定安全对话签发狭窄豁免"
- Altman 回应：欢迎联邦统一安全框架，但认为无需等待反垄断豁免或立法
- 联邦立场：特朗普宣布组建 AI 任务组、任命 AI 事务负责人，但拒绝新增约束，称减速呼吁为"阴谋"

# 今日重要论文

## When EOS Tokens Disagree: Understanding Length Inflation in On-Policy Distillation (arXiv:2609.20511)

9 月 17 日提交的论文（Microsoft 与 UNC 合作）定位了在线策略蒸馏（OPD）中一个长期被误判的现象：学生模型的回答越写越长、甚至耗尽生成长度预算，根因往往不是奖励设计或数据，而是基础学生模型与后训练教师模型把停止概率放在了不同的 EOS token 上——即便两者声明的停止集合看起来完全一致，这种错配也会压制学生偏好的终止动作，同时教师的替代终止又无法可靠迁移。论文验证了"只对齐解码停止集合"并不够用，而把功能等价的多个 EOS token 视为同一个语义停止动作可以显著缓解长度膨胀，且在 Qwen3、Llama、Gemma 三个模型家族上均成立；在 400 步长程 K2-Horizon 训练中，作者还发现终止对齐之后仍存在一个晚期的独立长度膨胀，说明终止错配重要但非唯一来源。实现已开源，包含五条件 EOS 消融。

链接: https://arxiv.org/abs/2609.20511

# 今日重要开源项目

## browser-use/jev-ultrafast

browser-use 与 TypeSafe 合作发布的浏览器智能体参考实现（9 月 16 日创建，MIT，约 8300 星）。它把动作空间改造成"动态索引表"：每次观测生成带编号的元素表，Jev 在一次请求里同时决定操作（CLICK、TYPE_TEXT、SELECT、SCROLL_UP/DOWN、WAIT、DONE、BLOCKED）与目标元素编号，只有在操作是 TYPE_TEXT 时才调用一个小模型生成文本——两个决策共用一次网络往返，且只向模型提供当前受支持的操作与兼容元素，避免无效动作。官方演示中从苏黎世到伦敦的 Google Flights 搜索（含实际文本生成与加载等待）耗时 7.1 秒。它的价值在于展示了 System One 模型如何把 agent 循环中的判断层从 LLM 中剥离，同时保留可测量的确定性执行路径。

链接: https://github.com/browser-use/jev-ultrafast

# 趋势观察

三条线在今天交汇。第一，智能体插件与技能生态的信任模型已经崩塌到与生态规模相等的程度：Plugin4Shell 证明分布式分发层的 SHA pinning 在客户端从未真正被校验，而自动更新把攻击变成零点击；与此同时 DeepSeek Harness 生态仍在扩张，"万物皆插件"的架构与"插件不可信"的现实被同时放大——插件注册表正在成为下一个需要签名、透明日志与可验证构建的攻击面。第二，治理在三条轨道上分裂：白宫以"AI Force"和 AI 事务负责人替代监管，加州以行政令绕过立法僵局、先行建设第三方审计能力，而司法系统首次被要求裁定"协调减速"是否属于横向垄断——这意味着下一轮争议的核心是"谁有权出具证据、以及谁来承担不减速的代价"。第三，成本结构正在被重新定价：Jev 把判断层做到 400 倍便宜、浏览器 agent 以 7 秒完成一次跨城航班搜索，说明大量 agent 推理其实不需要前沿对话模型；而 OpenAI 五年 2780 亿美元现金缺口与 Anthropic 的 IPO 前发布节奏，则说明前沿能力的那一端仍在以资本换时间。两者叠加的结果是，"减速"第一次同时成为法律问题、会计问题和架构选择问题。
