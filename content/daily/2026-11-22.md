# AI Daily Digest - 2026-11-22

## Executive Summary

Today's throughline is that AI systems now run inside other people's infrastructure, and the bill for that is arriving on three fronts at once. Amazon Threat Intelligence disclosed that a suspected China-nexus actor pointed the open-source Cairn agent framework at universities in East Asia and got from API mapping to a root shell in roughly eleven minutes, on a MONAI Label path-traversal flaw that nobody had reported before. Dragos published the first large measurement of what happens to a prompt after it leaves your network: two million canary-laced requests, three inference providers compromised, marketplace resellers reading prompts through ordinary logging, and Zero Data Retention flags that did not survive the first hop. Enforcement moved from entity lists to process nodes as the Commerce Department's remote-access rule took effect and TSMC and Samsung suspended previously permitted orders at 16nm and below. On the product side Thinking Machines put Inkling 2 Mini's weights out under Apache 2.0 at 26.4B total parameters in a roughly 20GB footprint. In research, the Agent AlphaXiv experiment reports 936 agents producing 936 preprints in twelve weeks, with 77 of 156 reviewer objections overturning headline conclusions once they were converted into executable tests.

## 1. Amazon: Cairn Agents Found a MONAI Label Zero-Day and Had Root in About Eleven Minutes

### What Happened

Amazon Threat Intelligence published an account on November 20 of a campaign it detected in September, in which a suspected China-nexus actor ran the open-source Cairn framework — a legitimate platform for autonomous penetration-testing agents — against internet-exposed instances of MONAI Label, an open-source tool for AI-assisted annotation of medical images. Amazon reconstructed the intrusion only because the operator's own Cairn control panel was sitting on the internet without authentication on September 10, exposing its prompts, task configuration and agent output. The records show a roughly 48-hour campaign against IP addresses belonging to universities in East Asia outside mainland China, with the operator handing the agents a target list and the instruction to obtain shell access. Against one target the agents mapped the application's API, found an upload endpoint whose filename parameter allowed path traversal, and were writing arbitrary files on the server within about eleven minutes. In a separate session they planted a Python reverse shell in a file loaded at interpreter startup, triggered a training endpoint to spawn a new process, and obtained a shell running as root, then pivoted through an attacker-supplied proxy into a second university network running the same software. MONAI Label's maintainers published a critical advisory on November 18 covering versions 0.8.5 and earlier, which run without authentication by default; a fix was merged on October 19 but no patched release existed at the time of the advisory. Amazon says it assesses with high confidence that the flaw was a zero-day.

### Why It Matters

This is the first public case where adversary-controlled agents discovered and weaponized a previously unknown vulnerability during a live intrusion, rather than chaining bugs that were already documented. That changes the arithmetic for anyone running research-grade open-source tooling: MONAI Label is the kind of software small academic and hospital teams deploy with defaults intact, because authentication is off by default and the users are researchers, not sysadmins. The eleven minutes from API map to arbitrary file write also compresses the defender's window below the time most security operations centers take to triage a single alert, which is exactly the argument Amazon's CISO made. And the operator's own panel being unauthenticated is a useful reminder that automation on both sides is now running with the operational hygiene of a hobby project.

### Key Technical Points

- Attacker tooling: Cairn, an open-source framework that runs AI agents as automated penetration testers; the operator's panel was reachable without authentication, exposing prompts and run history
- Campaign window: roughly 48 hours around September 8-10, 2026, targeting East Asian university IPs outside mainland China
- Vulnerability: path traversal (CWE-22) in MONAI Label's datastore upload endpoint, allowing arbitrary file writes to servers with no account required
- Timeline claim: about eleven minutes from API enumeration to arbitrary file write; root shell obtained in a later session via a reverse shell in a startup-loaded Python file plus a triggered training endpoint
- Advisory: GHSA-qc22-rmgc-vg94, rated critical, affecting MONAI Label 0.8.5 and earlier; fix merged October 19, patched release not yet available
- Attribution and confidence: Amazon assesses high confidence the flaw was a zero-day because no prior advisory, issue or fix existed; a CVE has been requested

## 2. Dragos Seeded Two Million Prompts With Canaries and Found Three Inference Providers Compromised

### What Happened

Dragos chief research officer HD Moore published a study on November 19 built on roughly two million prompts sent to widely used inference services between July and November 2026, each carrying canary material: a working AWS key tied to an empty account with full logging, a DNS name, and a URL, all unique per request so that any hit maps back to the exact prompt, model, router and privacy setting that carried it. Three findings came out. First, at least three AI providers showed evidence of compromise: in the largest case a couple of hundred AWS keys, each sent in exactly one request to one provider during short windows in late October, were all subsequently used, including keys that came from requests the provider had rejected before any model ran, which points at traffic being copied at request intake. Second, resellers operating through an AI inference marketplace could view and retain customer prompts using standard logging, with no exploit required. Third, privacy settings did not hold end to end: an unnamed Chinese AI lab fetched the secret URLs embedded in more than half of the prompts sent to its models, including roughly two thirds of the requests marked as zero data retention, with the fetches typically arriving two to three days after the request; one planted URL surfaced in a Feishu chat 24 days later. Dragos frames the result as a visibility problem rather than a single vendor bug, and notes that no evidence in this work shows prompts being used for training.

### Why It Matters

A privacy flag is a contract between the first two hops, not a property of the data. Once inference is resold through marketplaces, routed across providers and mirrored into evaluation and observability pipelines, "zero data retention" describes an obligation at one boundary while the prompt continues to exist at several others — and the operator who chose the cheap route has no way to observe the difference. The practical lesson is measurement: unique per-request canaries turn an unanswerable question about supply chains into an ordinary log query, and the fact that credentials from rejected requests were still stolen says intake itself has to be in scope for anyone doing a vendor review.

### Key Technical Points

- Method: roughly 2 million prompts over five months, each with a unique AWS key (real key on an empty account with full CloudTrail logging), DNS name and URL; Thinkst Canarytokens for the proof of concept, then a purpose-built seeding service deriving per-request material
- Compromise evidence: at least three providers; largest case involved a couple of hundred keys, each used in exactly one request during short late-October windows, all stolen
- Intake exposure: some stolen keys came from requests the provider had rejected before any model ran, indicating copying at the provider's front door
- Reseller exposure: multiple sellers on an AI inference marketplace could view and retain customer prompts through standard request logging, without exploiting anything
- Retention failure: a Chinese lab's systems fetched secret URLs from more than half of prompts sent to its models between July and October, including roughly two thirds of those marked zero data retention; fetches arrived two to three days later
- Persistence: one planted URL appeared in an internal Feishu chat 24 days after submission

## 3. Thinking Machines Puts Inkling 2 Mini Weights Out at 26.4B in a Laptop Footprint

### What Happened

Thinking Machines released Inkling 2 Mini on November 20 with open weights on Hugging Face under Apache 2.0: a looped-transformer mixture-of-experts model with 26.4 billion total parameters and 3.4 billion active, a one-million-token context window, and text-plus-image input with text output, in a memory footprint of roughly 20GB that the company demonstrated running offline on a MacBook Pro. The architecture is the interesting part — rather than scaling parameters, the model runs its middle layers three times per token, buying depth without proportional weight growth. It ships alongside Tinker for hosted inference and customization. Independent review started the next day: Plotly ran it through the data-analysis exam it applies to every release and it passed 36 of 43 questions, 84%, three fewer than Inkling 2 Small, which the lab describes as the best result of any U.S. open-weight model small enough to run on a Mac mini. On OpenRouter, Prime Intellect serves it at $0.10 per million input tokens and $0.40 per million output tokens.

### Why It Matters

The open-weight race in 2026 has mostly been a scale race, and the models worth downloading have needed a workstation at minimum. A 3.4B-active model that runs in 20GB and lands within a few questions of larger U.S. open-weight peers shifts the constraint from hardware to willingness to ship weights, which is precisely the gap that Chinese labs have been filling. The looped-transformer choice also matters beyond this model: if repeating middle layers per token is a cheaper route to agentic coding quality than adding parameters, the efficiency frontier and the architecture literature move together, and the next round of open releases will be judged on depth-per-token rather than parameter counts.

### Key Technical Points

- Architecture: looped transformer with mixture-of-experts; middle layers executed three times per token
- Scale: 26.4B total parameters, 3.4B active; one-million-token context; multimodal input (text and image), text output
- Footprint: roughly 20GB, demonstrated running offline on a MacBook Pro; company positions it for agentic coding on laptops
- Release terms: Apache 2.0 weights on Hugging Face, plus managed inference and customization through Tinker
- Third-party result: 36 of 43 on Plotly's data-analysis exam (84%), three questions behind Inkling 2 Small
- Serving: available on OpenRouter through Prime Intellect at $0.10 input and $0.40 output per million tokens

## 4. Agent AlphaXiv: 936 Agents Published 936 Preprints in Twelve Weeks, and Most Headline Claims Did Not Survive Testing

### What Happened

A preprint describing the Agent AlphaXiv experiment reports what happened when 936 autonomous agents, released by 35 human-run laboratories including Stanford, MIT and ETH Zurich, were given an isolated research ecosystem with its own preprint server for twelve weeks starting in mid-August. The agents exchanged about 9,500 messages across 229 chat rooms and produced 936 studies spanning machine learning, solar physics and audits of medical research, with each paper shipped alongside its code, data and model. Behaviour beyond paper count is the substance of the report: agents challenged each other's experiments, corrected and retracted work, reviewed code, and late in the window founded a Journal of Agent Research whose four-model blind review panel could recompute headline results from the submitted artifacts. When major reviewer objections were converted into executable tests, 77 of 156 objections overturned the original headline conclusions. The authors also report that human-written papers scored higher on novelty and significance than agent-written ones, a comparison that itself relied on AI judges, and describe the work as exploratory and not peer reviewed.

### Why It Matters

The interesting number here is not 936 papers; it is 77 out of 156. Research review has always depended on objections that nobody bothers to test, and this experiment shows that turning an objection into a runnable check is both cheap for agents and frequently fatal to the claim. That reframes autonomous science as a verification problem rather than a generation problem, and it suggests where human oversight should sit: not in reading more papers, but in deciding which objections get compiled into tests. The results also cut against the framing that agent-only ecosystems will simply outproduce human labs — by the study's own measure, novelty and significance did not improve.

### Key Technical Points

- Scale: 936 agents from 35 human-run labs, about 9,500 messages across 229 chat rooms, 936 studies over twelve weeks from mid-August 2026
- Infrastructure: an agent-only preprint server; each paper published with code, data and model artifacts
- Review mechanism: a late-formed Journal of Agent Research with a four-model blind review panel that could recompute headline results from submitted code and data
- Central result: when major reviewer objections were converted into executable tests, 77 of 156 objections overturned the original headline conclusions
- Comparative finding: human papers scored higher on novelty and significance, though the judging was done by AI models
- Status: exploratory preprint, not peer reviewed; authors position it as an ecosystem experiment rather than a capability claim

## 5. TSMC and Samsung Suspend Some 16nm-and-Below Orders From Chinese Designers as the Remote-Access Rule Bites

### What Happened

The Commerce Department's interim final rule on remote access to advanced semiconductors took effect on November 19, and foundries moved within hours. The Financial Times reported that TSMC and Samsung had suspended some shipments to Chinese customers until new US licences are secured, and Reuters reported that TSMC told affected Chinese chip designers that orders at 16-nanometer processes and below are halted unless they hold an export licence or a valid exception. What changed is procedural as much as technical: the previous regime let TSMC screen a customer's design itself and clear orders it judged to fall outside the controls, and the new rule removes that route, so advanced nodes are effectively presumed controlled and the burden of proof moves to the customer and the licence file. Without a licence or exception, affected designers are generally limited to 28nm and 40nm, and cannot use high-bandwidth memory or advanced packaging. One source said some Chinese AI chip designers had still been accessing 7nm production before the rules took effect. TSMC issued no statement; its shares closed at $352.09, down 2.93% and 27.5% below the October 5 record.

### Why It Matters

Export control has been drifting from entity lists toward capability presumptions for two years, and this is the cleanest example yet: the trigger is no longer who you are or what the chip does, but which process node you want and whether you can prove an exception. That makes the licensing queue, not the fab, the binding constraint for Chinese accelerator startups, and it explains why the rule was paired with the earlier measure on remote access to overseas data centres serving Chinese customers — the intent is to close the manufacturing and the access routes in the same window. For everyone else the read-through is that foundry compliance is now fast and automatic, which shortens the interval between a rule's effective date and its commercial consequences to roughly zero.

### Key Technical Points

- Rule: Commerce Department interim final rule, Addressing Remote Access to Advanced Semiconductors, effective November 19, 2026
- Foundry action: TSMC and Samsung suspended some previously permitted shipments to Chinese customers pending new licences, per Financial Times and Reuters
- Node threshold: orders at 16nm and below halted absent a US export licence or exception; earlier reporting indicated Chinese designers had retained some 7nm access before the change
- Procedural shift: the foundry's own design-screening exemption route is removed, so advanced nodes are presumed controlled and the burden of proof moves to the customer
- Fallback: without a licence, affected customers are generally limited to mature 28nm and 40nm processes, with no HBM and no advanced packaging
- Market reaction: no TSMC statement; shares closed at $352.09, down 2.93% and 27.5% below the October 5 record close

# Important Paper of the Day

## CompAct-Bench: A Benchmark for Working-Context Compaction in Long-Horizon Agent Tasks

Working-context compaction is the mechanism that lets long-horizon agents keep going past their input limits: history gets summarized, and execution resumes from the summary. This benchmark (arXiv:2611.25673, submitted November 19) treats compaction as a measurable ability rather than a utility function. Starting from successful agent trajectories, it inserts compaction boundaries at different stages of execution, has the model under evaluation compress everything that came before the boundary, and then lets the same executor continue the original task, so that downstream task accuracy isolates the cost of the compression. To compare compactors fairly, evaluation runs under controlled retention ratios using a lightweight iterative ratio-adjustment procedure. The task mix spans information seeking (BrowseComp), software engineering (SWE-bench) and workspace-oriented work through an internal CompanyBench suite. The headline is that compaction stays highly lossy even for frontier models: Claude- and GPT-family models perform strongest overall, yet substantial degradation persists under aggressive compaction. The sharper finding concerns the shape of the failures — not just omitted information but distorted task state, with unresolved issues turned into apparent conclusions or previously established results forgotten, which produces confidently wrong decisions or redundant re-execution. The lesson for anyone shipping a long-running agent is that a summary which retains the relevant facts can still hand back a corrupted picture of where the work stands.

Link: https://arxiv.org/abs/2611.25673

# Important GitHub Project

## erkamyaman/rust-anything

A different answer to the code-rewriting problem: instead of translating source, it records what the original application actually does — CLIs, HTTP servers, and other behaviours — and then has a coding agent rebuild the thing in Rust one piece at a time, checking each piece against that recording before moving on. The claim is verification rather than translation, which is the part that usually gets skipped when an agent is handed a rewrite. Created on November 16 and already at 7,389 stars with 189 forks under MIT, published on both crates.io and npm, with native binaries for macOS, Linux and Windows and a translation set covering twenty-plus languages. It belongs to the same family as the clean-room rewrite tooling that has been climbing GitHub this month, and its practical value is the same: the recording becomes the test oracle, so a rewrite can be accepted or rejected by observation rather than by review.

Link: https://github.com/erkamyaman/rust-anything

# Trend Observation

Three separate stories today describe the same structural shift: AI behaviour is now an operational fact in systems that were never designed for it, and the accountability arrives before the instrumentation does. Attackers' agents found a genuine zero-day in eleven minutes while defenders still measure triage in hours; inference customers cannot verify a retention promise past the first hop because nobody has instrumented the second; foundries cannot clear a design themselves any more, so the licence queue becomes the schedule. In all three cases the missing piece is measurement — canaries for privacy, patched-release discipline for research software, executable tests for research claims, replayable records for agent governance. The second thread is architectural: looped depth in Inkling 2 Mini and context compaction in CompAct-Bench are both arguments that capability per byte matters more than capability per parameter, and that the harness, not the model alone, decides whether a long task survives its own history. The third is that verification keeps migrating from prose to machinery — 77 of 156 objections became tests and the claims fell, which is exactly what a review culture that measures rather than opines would look like.
